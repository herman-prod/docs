## How to Get Listed

### AARM Conformant

To be listed as AARM-conformant, your product must:

1. Satisfy all MUST requirements (R1-R7) as defined in the [Conformance Requirements](/conformance/requirements)
2. Complete the [Testing Protocol](/conformance/testing) and provide evidence
3. Submit verification results via [GitHub](https://github.com/aarm-spec/aarm/issues)

### AARM Aligned

To be listed as AARM-aligned:

1. Your product addresses one or more aspects of the AI runtime security problem
2. Submit a brief description of what you're building and how it relates to the problem space
3. No conformance testing required

company:
  name: "Company Name"
  logo: "URL or file path to logo (square, min 200x200px)"
  description: "Brief description of what you're building (1-2 sentences)"

  category: "conformant" | "aligned"

## Conformant vs Aligned

| | AARM Conformant | AARM Aligned |
|---|---|---|
| **Meaning** | Product satisfies AARM specification requirements | Company is building in the same problem space |
| **Verification** | Testing protocol completed | Self-declared |
| **Requirements** | R1-R7 (Core) or R1-R9 (Extended) | Working on runtime action security |
| **Commitment** | Explicit implementation of spec | Problem-space alignment |
| **Best for** | Companies building AARM-native solutions | Companies with related approaches or complementary products |
