## Abstract

Large language models have evolved from text generators into autonomous agents capable of executing consequential actions across enterprise systems. This evolution introduces a runtime security gap: existing security paradigms—SIEM, API gateways, firewalls, prompt guardrails—were not designed for AI-driven actions that are irreversible, execute at machine speed, compose into policy violations, and originate from potentially compromised orchestration layers.

This paper introduces Autonomous Action Runtime Management (AARM), a system specification for securing AI-driven actions at runtime. AARM defines a security system that intercepts actions before execution, evaluates them against organizational policy, enforces authorization decisions, and records tamper-evident receipts for forensic reconstruction.

We formalize the problem space, characterize threats including prompt injection, confused deputy attacks, and compositional data exfiltration, and propose three implementation architectures with distinct trust properties. We specify minimum conformance requirements enabling objective evaluation of AARM implementations.
